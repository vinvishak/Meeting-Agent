# Implementation Plan: GitHub PAT Client

**Branch**: `008-github-pat-client` | **Date**: 2026-05-02 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/008-github-pat-client/spec.md`

## Summary

Implement a GitHub REST API client using Personal Access Token (PAT) authentication. The client syncs commits and pull requests from configured repositories, extracts Jira ticket keys via regex linking, integrates with the existing APScheduler-based sync worker, exposes three new read-only API endpoints, and wires real GitHub data into the Prism dashboard's currently-placeholder GitHub nodes.

## Technical Context

**Language/Version**: Python 3.12+  
**Primary Dependencies**: `httpx` (already present), `re` (stdlib), `pydantic` v2 (existing), `pydantic-settings` (existing), `sqlalchemy` 2.x (existing), `alembic` (existing), `fastapi` (existing), `apscheduler` (existing)  
**Storage**: SQLite via existing Alembic migrations — new migration `002_github_schema.py` adds 4 tables  
**Testing**: `pytest` + `pytest-asyncio` (existing setup)  
**Target Platform**: Local development server (macOS/Linux)  
**Project Type**: Web service (existing FastAPI backend)  
**Performance Goals**: Incremental sync < 30s for 15-min window; full sync < 5min for 50 repos  
**Constraints**: No new packages; respect GitHub 5000 req/hour PAT rate limit  
**Scale/Scope**: POC — single org, up to ~50 repos

## Constitution Check

### Gate 1: Modular & Clean Code (Principle I)
**Status**: PASS  
New module `src/ingestion/github_client.py` has exactly one purpose (GitHub HTTP + parsing). Route handler `src/api/routes/github.py` owns one concern (HTTP response shaping). Sync logic in `sync_worker.py` is isolated in `_sync_github()` function. No god classes.

### Gate 2: Single Responsibility (Principle II)
**Status**: PASS  
- `github_client.py`: GitHub REST API only — no DB, no scheduling
- `sync_worker._sync_github()`: orchestration only — calls client + repositories
- `github.py` routes: response shaping only — no business logic
- New repository methods: persistence only

### Gate 3: Test-First (Principle III)
**Status**: CONDITIONAL PASS  
Unit tests for regex extraction and pagination logic are required. Integration tests for the GitHub client require a live PAT (or VCR cassettes). Given POC scope, tests are scoped to unit tests for deterministic logic (Jira key extraction, rate limit header parsing) and a manual integration scenario via quickstart.md. Full integration test suite is a post-POC task.

### Gate 4: Agent Composability (Principle IV)
**Status**: PASS  
`GitHubClient` is independently invocable via `async with GitHubClient() as client:`. `_sync_github()` accepts no implicit global state beyond `Settings` (same pattern as `_sync_project`). All I/O is structured.

### Gate 5: Simplicity First (Principle V)
**Status**: PASS  
No new packages. No repository pattern class introduced — methods added directly to a `GitHubRepository` class consistent with existing code. No webhook infrastructure. No caching layer. Simplest path that satisfies the spec.

## Implementation Notes

### src/config.py additions
```python
github_pat: str = ""
github_org: str = ""
github_repos: str = ""  # empty = all repos; comma-separated = specific repos
```

### github_client.py design
Mirrors `jira_client.py` exactly:
- `GitHubClient` as async context manager using `httpx.AsyncClient`
- Base URL: `https://api.github.com`
- Headers: `Authorization: Bearer {pat}`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`
- Methods: `list_repos()`, `list_commits(repo, since=None)`, `list_prs(repo, since=None)`
- Pagination: loop `Link: <url>; rel="next"` header
- Rate limiting: check `X-RateLimit-Remaining`; if 0, sleep until `X-RateLimit-Reset`
- Retry: same exponential backoff pattern as JiraClient (3 retries, 2^attempt seconds)
- Pydantic response models: `GitHubRepoInfo`, `GitHubCommitInfo`, `GitHubPRInfo`

### Jira key extraction
```python
import re
JIRA_KEY_RE = re.compile(r'\b[A-Z][A-Z0-9]+-\d+\b')

def extract_jira_keys(text: str) -> list[str]:
    return list(set(JIRA_KEY_RE.findall(text or "")))
```
Applied to: commit message, PR title, PR body[:2000].

### sync_worker._sync_github()
Called at end of `run_sync_cycle()`, after Jira sync and transcript ingestion. Silently skips if `GITHUB_PAT` is not configured (same pattern as `_ingest_transcripts()`).

### Frontend patch (frontend/index.html)
Add `fetchGitHubStatus()` function called during page load and on tab switch to "Org Overview". Updates `data-status` attribute on `[data-type="github"]` tree nodes from `inactive` → `active` or `stale`.
